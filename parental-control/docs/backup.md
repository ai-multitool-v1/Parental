# Cloud Backup System (v1.3.0) — Consent-Based Automatic Backup

Status: **implemented** (web + Android + Cloud Functions + Firestore rules)
Applies to: every child device paired to the platform. The **parent manages everything from the Web Dashboard — there is no parent Android app.**

---

## 1. Product surface

Four independent, consent-gated categories:

| Category | Android source | Runtime permission | Notes |
|---|---|---|---|
| Photos | `MediaStore.Images` | `READ_MEDIA_IMAGES` (33+) / `READ_EXTERNAL_STORAGE` (≤32) | delta via `DATE_MODIFIED` |
| Videos | `MediaStore.Video` | `READ_MEDIA_VIDEO` (33+) / `READ_EXTERNAL_STORAGE` (≤32) | same; streaming upload |
| Contacts | `ContactsContract` | `READ_CONTACTS` (+`WRITE_CONTACTS` restore) | delta via `CONTACT_LAST_UPDATED_TIMESTAMP` (API 26+; 21–25 full-sync) |
| SMS (optional) | `Telephony.Sms` | `READ_SMS` | **restricted permission** — see §7 |

### Dual opt-in + permission (the triple gate)

A backup runs **only when all three are true at the moment of processing**:

1. **Parent policy** — `devices/{id}/backupPolicy/current` (written ONLY by the `backupSetPolicy` callable; direct client writes denied by rules).
2. **Child consent** — `devices/{id}/backupConsent/current` (written by the child app only after the visible in-app Allow dialog; shape-locked in rules).
3. **Runtime permission** — checked right before every scan/upload; revoked ⇒ module stops gracefully.

### Remote ON/OFF semantics (requirement 7)

* **OFF**: new uploads stop. Queued uploads hit the **server pre-check** (`backupCreateUploadUrl` re-validates policy + consent + ban for that exact item) and are flipped to `CANCELLED (POLICY_DISABLED)` — even if the device was offline when the toggle happened.
* **ON**: eligible `CANCELLED(POLICY_DISABLED)` items return to `PENDING` and the pipeline resumes.

## 2. State machine & duplicate prevention (requirements 12)

```
PENDING ──createUploadUrl(server)──► UPLOADING ──completeUpload(server, HEAD-verified)──► UPLOADED
   ▲                                    │                                          FAILED / CANCELLED (device or server)
   └────── resume (policy re-enabled) ──┘
```

* **Deterministic item id** — `itemId = sha256("{deviceId}|{category}|{sourceKey}")` where the sourceKey binds the content identity (media id + modified + size; contact id + lastUpdated + payload hash; sms id + date + payload hash). Re-detecting the same content maps to the **same document id**, so duplicates are impossible by construction (`create()` cannot overwrite).
* `UPLOADED` is reachable **only** through `backupCompleteUpload`, which HEAD-verifies the ciphertext object actually exists in the private bucket — a device can never fake a successful backup (rules + function cooperate).
* States are exactly `PENDING | UPLOADING | UPLOADED | FAILED | CANCELLED`; the dashboard offers retry for FAILED and shows the last error code.

## 3. Encryption & key management (requirements 10, 15)

* **AES-256-GCM** (128-bit tag) on-device via `CryptoEngine`:
  * fresh 96-bit **SecureRandom IV per item** (stored base64 in item metadata — not a secret);
  * streaming: `InputStream → CipherOutputStream → temp file` with 64 KiB buffers — multi-hundred-MB videos never enter RAM (requirement 14); upload uses `HttpURLConnection.setFixedLengthStreamingMode` (RAM-constant);
  * integrity is cryptographically enforced by the GCM tag at decrypt time.
* **DEK escrow** (`functions/src/lib/backupKey.ts`):
  * one 32-byte DEK **per child** (not per device) — provisioned at pairing, stored in Firestore **only wrapped** (`AES-256-GCM` under a 32-byte **KEK in Secret Manager** `BACKUP_KEK`);
  * `backupGetKey` unwraps for (a) the paired child device (claims) for encryption, (b) a parent linked to that child for restore; every call is rate-limited and audited (`BACKUP_KEY_ACCESS`); **no key material is hardcoded, logged, or written to Firestore in plaintext**;
  * per-child (not per-device) keys are what make **phone-reset restore** work: after re-pairing, the same childUid resolves to the same DEK, and `backupListForChild` discovers restorable items across all devices of that child (`children/{childUid}/backupIndex`).

## 4. Storage — Cloudflare R2 (requirement 9)

* The R2 bucket is **fully private**. Credentials live only in Secret Manager (`R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET`) — **never in the APK or web bundle**.
* All transfers use short-lived **SigV4 presigned URLs** generated by Cloud Functions (`lib/r2.ts`, dependency-free node:crypto):
  * device upload PUT — 10 min TTL, bound to a **server-generated** object key `b/{deviceId}/{category}/{itemId}` (clients never choose the key);
  * parent download GET — 5 min TTL, requires parent-of-device link + `UPLOADED` state; audited.
* `backupCompleteUpload` HEAD-verifies the object and maintains `backupStats/current` (totalBytes, per-category counts, lastBackupAt) and the child-level `backupIndex` — all server-side, so neither side can inflate or hide usage.
* Unset R2 secrets ⇒ callables fail with `BACKUP_STORAGE_UNAVAILABLE` and items report FAILED with that code — honest degradation, never a fallback to insecure storage.

## 5. Firestore schema (metadata only — requirement 8)

```
devices/{deviceId}/backupPolicy/current        {version, updatedAt, updatedBy, categories{photos|videos|contacts|sms:{enabled}}}
devices/{deviceId}/backupConsent/current       {consent{photos|videos|contacts|sms:{granted,grantedAt}}, updatedAt}   ← child-writable only
devices/{deviceId}/backupItems/{itemId}        {deviceId, childUid, category, fileName, mimeType, sizeBytes,
                                                checksumSha256, state, attempts, lastErrorCode?, r2Key?, ivB64?,
                                                createdAt, updatedAt, uploadedAt?}
devices/{deviceId}/backupStats/current         {totalBytes, itemCounts{}, lastBackupAt{}, lastBackupAtAny}
children/{childUid}/backupKeys/current         {wrappedB64, keyVersion, kekVersion, createdAt, updatedAt}   ← zero client surface
children/{childUid}/backupIndex/{deviceId}     {deviceId, childUid, lastBackupAt, itemCounts{}, totalBytes}  ← restore discovery
```

**No photos/videos/contact/SMS content ever touches Firestore.** Rules additions are matrix rows T43–T50 (see `firestore.rules` tail); new composite indexes cover queue ordering and child-scoped device queries.

## 6. Android pipeline (org.setbd.parentcontrol.backup)

| File | Role |
|---|---|
| `BackupModels.kt` | categories, states, triple-gate contract |
| `CryptoEngine.kt` | AES-256-GCM streaming encrypt/decrypt + content-hash ids |
| `BackupKeyManager.kt` | DEK fetch (callable) + EncryptedSharedPreferences cache |
| `BackupPolicyRepository.kt` | live policy listener + offline cache + child-consent writer |
| `BackupItemRepository.kt` | deterministic-id enqueue (dedupe) + rules-conformant transitions |
| `BackupSources.kt` | MediaStore / Contacts / SMS scanners + delta cursors |
| `BackupWorkers.kt` | `BackupScanWorker` (reconcile) + `BackupUploadWorker` (server pre-check → encrypt → stream PUT → HEAD-verify) |
| `BackupScheduler.kt` | unique periodic (12 h) + event-driven jobs + `MediaStoreObserver` (debounced ContentObserver on media+contacts) |
| `RestoreClient.kt` | `backupListForChild` + contact restore (`WRITE_CONTACTS`, visible inserts) + streaming decrypt |
| `BackupSettingsSection.kt` | child consent UI (Settings) + `BackupQuickCard` (post-pairing setup card) |

Recovery (requirement 13): PENDING items live in Firestore, WorkManager re-runs `BackupUploadWorker` (12 h periodic + backoff retries), and `BootReceiver` re-arms schedules — process death and reboot both self-heal.

## 7. SMS — policy posture (requirement 5)

`READ_SMS` is a **Google Play restricted permission** (default handlers + vetted exceptions). The module:

* requests the permission only through the standard dialog, from the visible backup UI, after an explicit in-app explanation;
* degrades to an honest **UNSUPPORTED** state (dashboard badge + child UI notice) when the system will not grant it — Play-distributed builds will typically show this state;
* **never** attempts AppOps/default-SMS-app/bypass tricks;
* hashes the sender number before upload (no raw PII in metadata) and encrypts the payload with the same AES-256-GCM engine before it leaves the device.

## 8. Deployment prerequisites

```bash
firebase functions:secrets:set BACKUP_KEK            # openssl rand -base64 32
firebase functions:secrets:set R2_ACCOUNT_ID
firebase functions:secrets:set R2_ACCESS_KEY_ID
firebase functions:secrets:set R2_SECRET_ACCESS_KEY
firebase functions:secrets:set R2_BUCKET
# R2 CORS: allow PUT/GET on b/* from the app (no web client uploads —
# the dashboard downloads through presigned GET, so CORS GET may be
# scoped to the dashboard origin only).
cd parental-control/firebase && firebase deploy --only firestore:rules,firestore:indexes
cd ../functions && npm run build && firebase deploy --only functions
```
